## なぜ設計文書は収束しなかったか

コードは 22〜23 回目でほぼ指摘が出なくなったが、`docs/design.md` は毎回 5〜10 件の実害つきの新しい指摘が出た。理由は次の 5 つ。

1. 確かめる手段 (oracle) が無い。
   - コードは、テストと `./verify.sh` が直ったかを機械的に決める。仕様には無い。
   - 「実装者がこう読むと誤る」という筋書きは、どの文にもほぼ作れる。終了条件の「実害シナリオつき指摘の消滅」が、仕様ではほとんど満たされない。
2. 直すほど文が増える。
   - 1 回に 30〜60 箇所を書き換え、各回の差分は約 1000 行になった。
   - 足した規則が既存の規則と絡み、次の回にそこを指摘された。
   - 修正自体が誤りを持ち込んだ。箇条の融合と、測っていないものに「実測」と書いた出典が例。
3. 観点どうしが逆を向く。
   - 箇条書きか式か、注を足すか消すか。前の回の修正を戻す指摘が出て往復した。
   - 後半は、前の回の判断を守る却下で止めた。
4. まだ作らない部分まで見ている。
   - per_user や Code Mode の細部など、MVP の外の部分も仕様にある。レビューの面が広がった。
5. ブレーキが効かなかった。
   - 「同じ箇所に 3 回目の指摘で機構を作り直す」は `findings.md` で数える。設計文書の指摘は `findings.md` に記録していなかったので、数えられなかった。

改善案 (「最初にやること」の元):

- 仕様は MVP に絞る。実装とテストを先に作り、テストを判定の基準 (oracle) にする。
- 仕様のレビューは、観点と回数を絞る。
- 設計文書の指摘も `findings.md` に記録し、作り直しの規則を効かせる。

### 振り返りへ送った項目

レビューで「振り返りへ」と決めた項目。いずれも、この PR では直さず、実害の経路が確かめられていない。

- GitHub の挙動を測れなかったもの (`api.github.com/markdown` がセッションの範囲外):
  - 生の HTML の `href`・`src`・`srcset` 以外の属性。
  - `<kbd>` など img 以外の `html_inline` を含む見出しの id。
  - 列つきの行の anchor (`L10C5`)・`.md` の BOM・ファイルへのリンクの末尾の `/`。
  - 空のファイル・CRLF・CR だけ・`L01` の行番号の振り方 (今は検査できない違反にしている)。
  - 生の HTML の `href` で `%` の後に 16 進が無い名前 (今は不正な %-エンコードの違反)。
- root と固定の環境では作れないテスト (別 uid・chmod が効かない・`BASH_VERSINFO` が読み取り専用):
  - 中断の後始末で TMPDIR を消せない報告・`killGroup` が投げる経路・bash の版の確かめ。
  - 写す元が読めない通常ファイルの行・`deno test` の段の TMPDIR を消せない通常の経路の行。
- 競合や環境で、起きても理由つきで落ちるか、害が小さいもの:
  - `run-checks.ts` の `write` が O_NONBLOCK の stdout で WouldBlock を書き込みの失敗にする (対象の環境で、その stdout を作る親を確かめていない)。
  - `verify.sh` の写す先に本物のディレクトリが、分類と `ln` の間に置かれる競合 (`ln` はその中に作るので、利用者の物は壊れない)。
  - SIGKILL で残る `pre-push.verify-<pid>` を次の実行で消す案 (pid の生死で並行する `verify.sh` と区別する規則が増えるので採らなかった)。
  - `emptyGroup` の SIGKILL の後の回収に上限が無い (D 状態。止まった FS は段の前の git も止めるので、上限を置いても結果は正しくならない)。
  - 15 回目に直さないと決めたもの: 直接 `deno test` を回したときのテストの fixture の消去、`exec` の読みが reject したときのもう一方の読み端の cancel、finish の開始後の `importKeys` の書きによる ENOTEMPTY。
- `verify.sh` の `core.hooksPath` の読み取りで、git だけが 1 つの項目の途中 (NUL の前) で殺され、読み取りの子の shell が生き残って exit の項目を書く場合: 切れた項目と exit の項目がつながり、「出どころが file でない。想定外」で落ちる。誤って通ることは無いが、示す理由が誤る。直すには読み取りの機構の作り直しが要る。
- macOS で測っていないもの: bash 3.2 の `local LC_ALL=C` の照合。macOS の `killGroup` の PermissionDenied は、canon の測定で終わりかけのグループに 1000 回に 2〜5 回出るので、投げずに捨てている (前提が崩れたときの帰結はコメントに書いてある)。
